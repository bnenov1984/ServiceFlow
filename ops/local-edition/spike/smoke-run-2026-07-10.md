## Findings (all folded back into the scripts)

1. **Daemon inherits stdout pipe** — calling `pg_ctl start` directly inside any
   PowerShell pipeline hangs the pipeline forever (postgres holds the pipe handle).
   Fix: `Start-Process` with redirected-to-file handles. *This would have bitten the
   installer bootstrap in production.*
2. **PS 5.1 `Start-Process -Wait` waits for the process tree** — i.e. for the
   daemon, forever. Fix: `.WaitForExit()` on the process object.
3. **PS 5.1 `ExitCode` is `$null` unless `.Handle` was touched** — caused a false
   failure on a successful start. Fix: cache `$p.Handle` before waiting.
4. **`--data-checksums` was missing** from initdb — enabled now (silent-corruption
   detection on shop-grade disks; ~2 % write overhead is a fair price). Applied to
   spike + installer bootstrap.
5. **Timezone drift**: initdb inherited a wrong OS guess (`Europe/Kiev`). Config now
   pins `timezone = 'UTC'` (constraint C6); presentation stays Europe/Sofia app-side.
6. **Post-crash startup can be slow**: the `fsync` sweep of the data directory after
   unclean shutdown took **33 s** on this machine. Consequence for the product: the
   tray/health UX must show "възстановяване след прекъсване…" during recovery
   rather than looking hung; noted for Stage 6 tray work.

Findings 1–3 are exactly why the smoke run existed: the same code paths power the
installer bootstrap and the 05 restore wizard.
